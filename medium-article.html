Fine-Tuning an LLM With 6,144 Parameters on a Real Quantum Computer

IBM Research just showed that quantum circuit blocks can adapt a billion-parameter model using 2,730× fewer parameters than LoRA. I built an interactive demo to make the math visible.

Fine-tuning Llama 3.1 8B the classical way costs hundreds of millions of parameters and gigabytes of GPU memory. LoRA reduced that to millions. Now a 2026 IBM Research paper reduced it further — to 6,144 parameters — using 2-qubit quantum circuit blocks running on a real 156-qubit quantum processor.

The Problem: Fine-Tuning Costs Scale With Model Size

When a pre-trained LLM needs to learn a new task, you need to update its weights. The naive approach — full fine-tuning — updates all of them:

Llama 3.1 8B
├── 32 transformer layers
│   ├── Q, K, V, O projection matrices (each: 4096 × 4096)
│   └── MLP weights (up, down, gate projections)
└── Total trainable: ~8.59 billion parameters
    Memory (fp16): 16 GB just for gradients

That's before optimizer states. Adam adds another 2× for momentum. You need roughly 48 GB of VRAM to fine-tune Llama 8B with full precision. Most researchers and companies can't afford that.

LoRA (Low-Rank Adaptation, 2021) changed the game: instead of updating the full weight matrix W, you freeze W and add two small trainable matrices A and B beside it. Since A is (d × r) and B is (r × d), and r ≪ d, the parameter count drops dramatically:

LoRA with rank 8, Llama 3.1 8B:
  params = 32 layers × 4 projections × 2 matrices × 8 × 4096
         = 8,388,608   (~8.4M parameters, 16 MB in fp16)

Reduction vs full fine-tuning: 1,024×

LoRA is now the industry standard. But it still has millions of parameters. What if you could do the same thing with thousands?

The Quantum Answer: Cayley Unitary Adapters

The IBM Research paper (arXiv:2605.05914) introduces a fundamentally different adapter: a quantum circuit block that replaces the LoRA matrices with a unitary transformation built from 2-qubit quantum gates.

Here is the key insight. A 2-qubit quantum system has a 4×4 state space. A unitary matrix Q acting on that space satisfies QTQ = I — it preserves the norm of any input vector. That's not just mathematically elegant; it means the adapter can never amplify or destroy information in the base model's representations.

The paper parameterises Q using the Cayley transform:

Given a skew-symmetric matrix K  (K = −Kᵀ):

Q = (I − ½K)(I + ½K)⁻¹

Properties:
  • Q is guaranteed unitary: QᵀQ = I
  • K has exactly 6 free parameters for a 4×4 system
  • Differentiable: gradients flow through the Cayley formula

A 4×4 skew-symmetric matrix has 6 free parameters in its upper triangle. So each quantum adapter block uses just 6 trainable numbers — and the resulting transformation is provably unitary.

From 6 Parameters to a Gate Circuit

On real quantum hardware, you can't apply an arbitrary 4×4 matrix directly. IBM's Heron r2 processor has three native gates: SX (√X), RZ (rotation around Z-axis), and CZ (controlled-Z entangler). The paper decomposes each Cayley unitary into this gate set:

q0: ──SX──RZ──┬──SX──RZ──┬──SX──RZ──┬──SX──RZ──┬──SX──RZ──┬──SX──RZ──
              │          │          │          │          │
q1: ──SX──RZ──CZ─SX──RZ──CZ─SX──RZ──CZ─SX──RZ──CZ─SX──RZ──CZ─SX──RZ──

Gate count: 12 SX + 9 RZ + 3 CZ = 24 gates  |  Circuit depth: 19

Left: the canvas-rendered gate diagram for a 2-qubit Cayley block. Right: perplexity recovery simulation — the quantum adapter achieves 83% compression recovery, beating LoRA rank 8 (62%) with far fewer parameters.

Why 2 Qubits? The Noise-Expressivity Phase Transition

This is the most counterintuitive part of the paper. Why stop at 2 qubits? More qubits = more expressivity. But IBM's Heron r2 processor has a two-qubit gate error rate of λ = 11.9% per operation. The noise compounds:

Qubit count PPL degradation Relative to 2q Verdict
2 qubits 0.08% 1× ✅ Feasible today
3 qubits 2.80% 35× ⚠️ Problematic
4 qubits 12.50% 156× ❌ Unusable today

At 2 qubits, the hardware noise is so benign that the quantum advantage survives. At 3 qubits, quality collapses 35×. This is the synthesis feasibility frontier — 2 qubits is the sweet spot where quantum expressivity outpaces hardware noise on current processors.

The noise-expressivity phase transition plotted in the demo. The line goes from nearly flat at 2 qubits to 12.5% degradation at 4 qubits — a stark visual of why the paper uses 2-qubit blocks exclusively.

Building the Interactive Demo

I wanted to make every number in the paper interactive and explorable, so I built a full-stack demo from scratch.

Backend: FastAPI + NumPy Quantum Simulation

The backend is a FastAPI app in Python 3.12 with four endpoints. All quantum math runs in NumPy — no Qiskit, no PennyLane, no quantum hardware required.

The core simulation in quantum.py:

def make_skew_symmetric(params, n=4):
    """Build n×n skew-symmetric K from upper-triangle params."""
    K = np.zeros((n, n))
    idx = np.triu_indices(n, k=1)
    K[idx] = params
    K -= K.T          # K = −Kᵀ by construction
    return K

def cayley_transform(K):
    """Q = (I − 0.5K)(I + 0.5K)⁻¹  — guaranteed unitary."""
    I = np.eye(K.shape[0])
    Q = (I - 0.5 * K) @ np.linalg.inv(I + 0.5 * K)
    return Q

def simulate_circuit(input_vector, n_qubits=2):
    params = np.random.randn(6)       # 6 free Cayley parameters
    K = make_skew_symmetric(params)
    Q = cayley_transform(K)
    x = input_vector / np.linalg.norm(input_vector)  # amplitude encoding
    output = Q @ x
    return output, Q                  # QᵀQ ≈ I — verified on every call

The four API endpoints:

  • POST /api/analyze — compare all three adapter types for any model config
  • POST /api/circuit — simulate a Cayley block and return the gate sequence
  • POST /api/benchmark — parameter efficiency table across model sizes
  • GET /api/examples — three pre-built presets (Llama 8B, SmolLM2 135M, high-rank LoRA)

Frontend: React 19 + Canvas Circuit Diagram

The frontend is React 19 with TypeScript strict mode, Vite 6, Tailwind CSS 3, Recharts for charts, and Framer Motion for animations.

The most technically interesting component is the Quantum Circuit Visualiser. It uses a <canvas> element (not SVG) to render the gate diagram — critical for performance since animating 24 gates at 80ms intervals would cause jank with SVG DOM nodes:

// QuantumCircuitViz.tsx (simplified)
const canvasRef = useRef<HTMLCanvasElement>(null);

useEffect(() => {
  const ctx = canvasRef.current?.getContext("2d");
  if (!ctx || !circuitData) return;

  // Draw qubit wires
  for (let q = 0; q < nQubits; q++) {
    ctx.beginPath();
    ctx.moveTo(MARGIN, qubitY(q));
    ctx.lineTo(WIDTH - MARGIN, qubitY(q));
    ctx.stroke();
  }

  // Draw each gate
  circuitData.gate_sequence.forEach((gate, i) => {
    const x = gateX(gate.step);
    if (gate.gate === "SX")  drawSXGate(ctx, x, qubitY(gate.qubit));
    if (gate.gate === "RZ")  drawRZGate(ctx, x, qubitY(gate.qubit), gate.angle);
    if (gate.gate === "CZ")  drawCZGate(ctx, x, gate.qubit);
  });
}, [circuitData, animStep]);

What You Will Learn From This Demo

  1. The Cayley transform — how to generate a guaranteed-unitary matrix from 6 free parameters, and why unitarity matters for adapter stability
  2. Quantum amplitude encoding — how a classical vector is normalised to become a quantum state, and what that means for information preservation
  3. The noise-expressivity trade-off — why 2 qubits is the optimal size for current IBM hardware, and how to calculate the feasibility frontier
  4. Parameter scaling formulas — exact arithmetic for Full FT, LoRA, and Quantum adapters at any model size (try switching to SmolLM2 135M in the demo)
  5. FastAPI + React full-stack patterns — Pydantic v2 field constraints, async lifespan handlers, Canvas-based visualisations, and React 19 concurrent data fetching
